## Collection plan

1. Obtain consent and written intended-use rights for authentic source captures, including model training and retention policy. Prefer PSP sandbox/demo accounts or consenting contributors with protected identifiers. Authentic screenshot means an unedited original capture; it does not mean the depicted payment settled.
2. Target an initial **1,000 independently sourced originals**, balanced across at least five apps/templates, multiple device/OS generations, languages, light/dark themes and contributors. Produce controlled edited counterparts across amount, recipient, timestamp, reference, QR payload, insertion, removal, replacement, splicing and copy-move. This number is a planning target, not a guarantee of sufficient statistical power.
3. Capture both classes through the **same real, documented delivery paths**: WhatsApp device/app version, send mode, forwarding count, save/export path, resizing and genuine screen recapture. Preserve original bytes privately. Keep actual delivery separately labelled from software simulations.
4. Store edit masks, operator/session details, source original ID, template, device, contributor, label evidence, permission reference, checksum, transformations, redaction history and labels. Privacy changes themselves alter forensic signals: apply equivalent anonymization to both paired classes, record it, and never call a post-redacted file an untouched source.
5. Independently review labels and masks; explicitly flag ambiguous items. Keep QR strings/reference patterns fictional where possible. Do not put financial identifiers, speech recordings or private transaction histories into public Git.
6. Assign connected source/template/device/contributor/edit-session groups to train/validation/test **before training**. Reject identical hashes and review perceptual near-duplicates across groups. Source grouping alone is insufficient if all templates or contributors repeat across splits. Lock unseen app/device strata as a second external set. Never tune using either test set.
7. Compare GBDT and random forest feature baselines before a CNN/localizer. Compute features without label/provenance target leakage. Fit preprocessing and any calibration only on training/validation folds. Select an operating point with a stated FPR target on validation data. Record model version, feature schema, configuration, all manifest/split hashes, class distributions, dependencies, artifact SHA-256 and calibration provenance.
8. Independently evaluate ROC/PR, confusion metrics, paired ranking, robustness drift, mask metrics and confidence calibration. Bootstrap original groups, not transformations. For a target false-positive rate near1%, observing zero false positives in roughly300 independent negatives gives only an approximate95% upper bound near1% (rule of three); subgroup assurance requires sufficient independent negatives per subgroup. Correlated transformed copies do not supply that independence.
9. Promote only if predeclared discrimination, false-positive, calibration, localization and latency gates pass on locked data, with no critical subgroup regression. Otherwise preserve the operational engine and publish failed experiments honestly.
